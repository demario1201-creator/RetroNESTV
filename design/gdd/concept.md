# 游戏概念文档 — 网页版 NES 模拟器（CRT 复古游玩台）

> 版本：v0.1（概念阶段 / 精简 lean 评审）
> 作者：design-strategist（文策渊）
> 受众：主理人、美术导演、工程主程
> 平台：纯前端 Web 应用（Vanilla JS + Canvas，无框架）
> 模拟核心：jsnes（纯 JS，MIT）

---

## 0. 一句话定位

一台"长在网页里的旧电视 + 小霸王机身"，让你把 `.nes` 卡带（内置 / 上传 / 拖拽）插进去、按一下就开机进游戏——在任何设备的浏览器里复刻 8-bit 主机的游玩仪式感。

---

## 1. 创意支柱（动词优先 / 3 条）

每条支柱 = **动词 + 一句主张 + 设计含义**。支柱是后续所有功能取舍的仲裁标准，任何偏离支柱的需求需主理人特批。

### 支柱 1 · 还原（Recreate）
**用高保真 CRT 与开机仪式，复刻 8-bit 主机的"看屏幕"体验，而非"看网页"。**
- 设计含义：CRT 视觉（曲面屏 + 扫描线 + 辉光 + 机身外壳 + 通电开机动画）是产品灵魂，不是装饰开关的附属品；默认开启、可降级但不可省略。
- 取舍红线：若某功能会让画面"更像网页、更像模拟器窗口"，则否决。

### 支柱 2 · 即玩（Jump In）
**三步之内从开机到进游戏（选卡带 → 载入 → 点电视开机），零配置、零等待摩擦。**
- 设计含义：三种卡带来源（内置 / 上传 / 拖拽）必须汇入同一条"载入 → 游玩"主路径，UI 状态一致；载入越短、校验越安静，越符合支柱。
- 取舍红线：禁止在首屏放教程弹窗、账号登录、商店入口等任何阻断性前置。

### 支柱 3 · 随身（Carry）
**网页即开即玩，PC 键盘与移动端虚拟按键无缝切换，跨设备体验一致。**
- 设计含义：输入层抽象为统一的"意图(intent)"——D-Pad / A / B / Start / Select 八路；键盘与触摸只是两种输入源，逻辑共用。
- 取舍红线：不为移动端单独另做一套玩法或界面叙事；平台差异仅体现在"输入方式"与"入口可见性"上。

## 2. MDA 框架分析

> MDA = Mechanics（机制） / Dynamics（动态） / Aesthetics（美学）。以下结合 NES 模拟器特性拆解。

### 2.1 Mechanics（机制 — 系统"做什么"）
- **仿真内核**：jsnes 提供 6502 CPU + PPU（画面） + APU（声音）的纯 JS 仿真；输入为 8 路标准 NES 手柄信号（上/下/左/右/A/B/Start/Select）。
- **CRT 渲染管线**：Canvas 输出原始像素 → 后处理（曲面几何形变 + 水平扫描线 + 边缘辉光 + 暗角 + 机身外壳合成）。
- **卡带载入**：`.nes` 文件（iNES 格式）以 `ArrayBuffer` 读入 → 校验 NES 魔数 → 注入 `jsnes.loadROM()`。
- **开机动画**：独立的"通电瞬态"状态机（白点 → 亮线 → 滚屏 → 信号锁定 → 放大进入），叠加于 CRT 渲染之上。
- **存档（Should/Could）**：电池存档（SRAM 持久化）/ 即时存档（Save State）二选一或并存。
- **全屏（Should）**：浏览器 Fullscreen API 接管视口。

### 2.2 Dynamics（动态 — 玩家"玩出什么"）
- 玩家把"一个文件"变成"一段可玩记忆"——载入完成的瞬间是核心情绪高点。
- CRT 滤镜把"看网页"变成"看一台电视"，注意力从 UI 收束到屏幕内容，沉浸由视觉而非 UI 制造。
- **"拖卡带到电视机上"** 的手势强化了"插卡"隐喻，把数字文件操作拟物化，降低认知门槛。
- 移动端的虚拟按键改变手部姿态（双手握持、拇指操作），动态上等价于"换了手柄"，需在布局上补偿操作精度。

### 2.3 Aesthetics（美学 — 玩家"感受什么"）
按 LeBlanc 美学分类，本作主美学为：
- **Nostalgia（怀旧，主导）**：旧电视、小霸王机身、开机动画直接唤起客厅游戏记忆。
- **Sensation（感官质感，主导）**：扫描线/辉光/曲面带来的"模拟信号"视觉与 APU 方波音频的听觉复古。
- **Discovery（发现，次主导）**：内置卡带清单鼓励"试试没玩过的老游戏"。
- **Challenge（挑战，伴随）**：8-bit 游戏本身的操作/关卡难度，是胜任感来源。

> 设计注记：美学优先级 **Nostalgia + Sensation > Discovery > Challenge**。任何让"怀旧感"或"复古质感"打折的方案（如默认关 CRT、扁平化机身）都需主理人特批。

## 3. 范围分层（Must / Should / Could）

> 分层用于排期与验收。MVP 只含 Must；Should 进目标版本；Could 进愿景池。

### Must（MVP 必备）
- 内置卡带结构预留（manifest JSON，清单内容稍后由用户提供；先定结构）。
- 三种卡带来源入口可见：**内置选择 / 上传文件 / 拖拽到电视**。
- 卡带加载 → 点击电视 → 开机动画 → 进入游戏 的主流程闭环。
- 默认键盘映射（方向键/WASD 移动，J/K 或 Z/X 为 A/B，Enter/Shift 为 Start/Select），**可改键**。
- CRT 高保真渲染（曲面 + 扫描线 + 辉光 + 机身外壳 + 开机动画）。
- PC 浏览器可运行、可游玩、可退出返回。

### Should（目标版本）
- 移动端虚拟按键（方向键 + A/B + Select/Start）。
- 开机动画（白点展开 / 滚屏通电，可点击快进）。
- CRT 开关（高保真 ↔ 关闭/简化，供弱设备降级）。
- 全屏模式。
- 文件校验与友好异常：非 `.nes` / 魔数不符（损坏） / 超大文件，均回 Idle 并提示。

### Could（愿景池）
- 存档系统（电池存档 / Save State）。
- 卡带封面缩略图与内置清单网格浏览。
- 最近游玩记录 / 收藏。
- 物理手柄支持（Gamepad API）。
- 音量 / 滤镜强度（扫描线、辉光、曲面）调节面板。
- 分享链接（携带卡带 ID 或 ROM 摘要）。
- 云端同步存档。

## 4. 视觉锚点（给美术导演）

> 关键词 + 参考情绪，用于 art-bible 落地的方向对齐。详细资产规格由美术导演在 `design/art/art-bible.md` 展开。

1. **CRT 曲面屏** — 物理弧面玻璃 + 四周暗角（vignette），参考 80s 日立 / 东芝彩电显像管。情绪：厚重、真实、有重量。
2. **扫描线与辉光** — 水平 RGB 条纹 + 轻微光晕溢出，参考 CRT Shader / ShaderToy 经典后处理。情绪：模拟信号的温度感。
3. **小霸王机身** — 红白双色塑料外壳、金色印刷字面、顶部卡带插槽，参考小霸王 / FC 兼容机。情绪：国产童年、塑料质感、亲切。
4. **开机瞬态** — 白点 → 横向亮线 → 纵向滚屏噪点的"模拟信号唤醒"，参考 CRT 通电纪录片 / 老电视实录。情绪：仪式感、期待、时间感。
5. **暖色怀旧** — 偏暖的房间环境光（非纯黑背景），木质 / 地毯暗示，营造"客厅游戏"氛围而非"工具软件"。情绪：安心、私密、回忆。

## 5. 玩家心理学注解

### 5.1 自我决定论（SDT：自主 / 胜任 / 关联）
- **自主（Autonomy）**：三种卡带来源自由选；键位可改；CRT 开关自选——玩家掌控"如何进入游戏"。
- **胜任（Competence）**：8-bit 游戏操作难度高，需通过"上手即玩"的布局（默认键位合理、虚拟按键够大）与可选的轻提示降低门槛；通关 / 破纪录提供胜任反馈。
- **关联（Relatedness）**：核心弱项。内置卡带清单与"共同记忆"提供浅层关联；深关联（社区 / 分享 / 联机）放入 Could，不作为支柱支撑。

### 5.2 心流（Flow）
- 难度来自游戏本身（8-bit 关卡硬），**界面必须"隐形"**：载入越短、CRT 越真实、操作映射越直觉，玩家越容易入流。
- 防认知过载：首屏只保留"电视 + 三个来源入口"，不堆功能；异常提示用一句人话而非错误码。

### 5.3 目标用户（Bartle 玩家类型）
- 核心：**Explorers（探索者）**——乐于翻内置卡带、试没玩过的老游戏；**Achievers（成就者）**——以通关 / 高分老游戏为目标。
- 次要：**自定义意味的创造者倾向**——"上传自己的 ROM"带有"我的卡带我做主"的表达欲。
- 非核心：**Killers / Socializers**——本作无对抗 / 无强社交，不投资源。

## 6. 待确认事项（回主理人）
1. 内置卡带清单（id / name / file / cover）的具体内容由用户提供，本文档已预留 `manifest` 结构。
2. 文件大小上限建议 **8MB**（实际 NES ROM 通常 < 4MB），需主理人拍板。
3. 开机动画是否配"通电嗡声"等音频——涉及浏览器自动播放策略（需用户手势触发，点击电视本身即手势，可行），待定。
