# 美术圣经 · 网页版 NES 模拟器（高保真复古 CRT）

> 文档归属：游戏开发工作室 — 美术方向（林绘澄 / art-director）
> 适用项目：纯前端网页应用（Vanilla JS + Canvas，无框架），模拟核心 jsnes
> 评审强度：精简 lean —— 本圣经只规定**视觉方向与可落地规格**，不含实现代码。
> 目标体验关键词：「旧电视开机」「CRT 磷光质感」「80–90 年代中国家庭客厅怀旧」

---

## 0. 速读摘要（给工程主程）

- **三大视觉支柱**：旧 CRT 电视外壳（居中）+ 小霸王风格机身插画（下方装饰）+ 高保真 CRT 屏幕后处理（游戏画面叠加）。
- **CRT 叠加推荐实现**：见第 5 节。结论先行——**以 WebGL 片元着色器后处理为"高保真目标档"，以 CSS 合成叠层为"永远可用的基线档"**（基线档在 WebGL 不可用或用户开启减弱动效时兜底）。
- **可访问性基线**：至少做到 **Standard**（键盘可达 + `prefers-reduced-motion` 跳过开机动画），详见第 9 节。
- **配色主调**：暖米色塑料外壳 + 暖白/磷光屏 + 暖橙红强调色，背景为暗暖客厅环境光。

## 1. 时代基调与情绪（Mood）

**核心场景**：80–90 年代中国城镇家庭客厅。一台罩着布套或落了薄灰的 CRT 电视机，下方接一台小霸王（或兼容机）红白机机身，孩子蹲在地板上看《魂斗罗》。灯光偏暖、有尘絮在光里浮动，空气里是模拟信号的轻微"沙沙"静电。

**情绪目标**：怀旧（nostalgia）、温暖（warmth）、模拟质感（analog warmth）、颗粒与余晖（grain & phosphor afterglow）、轻微的"不完美"（轻微畸变、滚屏、噪点——这些不是 bug，是风格）。

**参考情绪词（供设计与评审对齐）**：
- 怀旧 Nostalgic · 暖黄灯光 Warm tungsten glow · 尘埃感 Dust motes
- 慵懒午后 Lazy afternoon · 邻里喧闹 Neighborhood hum
- 模拟质感 Analog warmth · 颗粒感 Film grain · 静电雪花 TV snow / static
- 荧光余晖 Phosphor afterglow · 通电瞬间 Powered-on spark · 圆润塑料 Rounded plastic

**NOT 要做**：高冷科技感、霓虹赛博、扁平极简、纯白背景。本项目拒绝"现代干净 UI"腔调。

## 2. 配色系统（Color System）

所有颜色以 sRGB HEX 给出。分为四大类：**外壳塑料 / 屏幕磷光 / 背景环境 / UI 强调**。游戏内画面本身使用 jsnes 原生 NES 调色板（不在此覆盖），本系统只规定"机器与外壳 UI"。

### 2.1 外壳塑料（TV shell & console body）
| 用途 | 名称 | HEX | 备注 |
|---|---|---|---|

| 外壳次色（侧/暗面） | 旧米黄阴影 | `#C7B188` | 用于倒角/阴影面 |
| 外壳深色描边 | 焦糖棕 | `#8A6E45` | 接缝、凹槽、文字丝印 |
| 高光点 | 暖白高光 | `#F7EFDC` | 顶部弧形高光带 |
| 散热/格栅 | 灰褐格栅 | `#9C8763` | 喇叭网、通风孔 |

### 2.2 屏幕磷光（Screen phosphor）
| 用途 | 名称 | HEX | 备注 |
|---|---|---|---|
| 通电亮屏（游戏画面底） | 暖白磷光 | `#F3E9C8` | 黑场时屏面微亮的暖白 |

| 屏面边缘暗角 | 边缘暗 | `#1A1206` | vignette 用，低透明 |

### 2.3 背景环境（Living-room backdrop）
| 用途 | 名称 | HEX | 备注 |
|---|---|---|---|

| 背景次色（墙面光斑） | 暖褐墙 | `#2E2519` | 顶部柔光晕 |

> 默认采用**暗暖背景**，让 CRT 屏幕成为视觉焦点。浅色背景仅作为可访问性/日间备选，需配套提高对比度（见第 9 节）。

### 2.4 UI 强调色（Accent / interactive）
| 用途 | 名称 | HEX | 备注 |
|---|---|---|---|
| 主强调（按钮/焦点环） | 暖橙红 | `#E8541E` | 80 年代红白机/复古橙 |
| 次强调（链接/提示） | 青蓝 | `#36C5D6` | 与暖橙形成冷暖对比 |

## 3. 电视机外壳设计（CRT TV Shell）

**总体比例**：外壳为横向圆角矩形，屏幕区为 **4:3**（契合 NES 原生分辨率 256×240 ≈ 4:3）。建议外壳宽高比约 **1.35 : 1**（宽略大于高，含边框与底部控制条）。

**可绘制结构（自上而下）**：
1. **顶盖弧形高光带**：外壳顶部一条宽度约 8–12% 壳高的暖白高光（参考 2.1 高光点），体现塑料反光。
2. **屏幕黑边（bezel）**：内嵌黑色/深褐边框，边框宽度约为屏幕短边的 **6–9%**，四角圆角半径约为屏幕短边的 **4–6%**。边框内侧有一圈更深的"玻璃陷落"阴影。
3. **屏幕玻璃**：4:3 显示区，承载游戏画面 + CRT 叠加（第 5 节）。玻璃周边可加一道极细的斜向反光高光（左上→右下）。
4. **底部控制条（底檐）**：高度约为壳高的 **14–18%**，容纳：
   - 左侧：电源指示灯（小圆点，灭=暗红 `#5A1E14`，亮=磷光绿 `#5FD17A` 带 glow）。
   - 中部：2–3 个旋钮（频道/音量），圆形，直径约为底檐高的 **40–55%**，带刻度凹纹。
   - 右侧：扬声器格栅（竖向或点阵条纹，用 2.3 灰褐格栅色）。
5. **支脚/支架**：底部两侧各一个梯形/圆柱小脚，高度约为壳高的 **5–7%**，颜色取外壳次色（暗面）。外壳可直接"坐"在下方小霸王机身上（见第 4 节），亦可独立支脚。

**绘制建议**：
- 用矢量（SVG）或 Canvas 路径绘制外壳，便于响应式缩放与主题换色（用 CSS 变量绑定 2.1 的 HEX）。
- 塑料质感靠**分层明暗 + 顶部高光带 + 边缘内阴影**实现，不依赖贴图。
- 所有圆角、旋钮位置用"相对屏幕尺寸的百分比"定义，禁止写死像素，确保 320px→1920px 自适应。

## 4. 小霸王机身插画规格（Console Body Illustration）

作为**页面下方装饰图案**，绘制一台横置的红白机/小霸王风格兼容机机身，与上方电视在视觉上"接驳"（电视支脚搭在机身上沿或紧邻）。

**轮廓**：横向圆角矩形机身，宽约为电视外壳宽的 **92–100%**，高约为电视壳高的 **22–28%**，圆角半径约为机身高的 **12–18%**。

**配色**：复用第 2 节——主色暖米白塑料 `#E4D6B8`，暗面 `#C7B188`，焦糖棕描边 `#8A6E45`；可加一抹经典"红白"分割：上盖米白、下体浅灰白，或前脸一条暖橙红饰带 `#E8541E`（呼应强调色）。

**部件位置（相对机身矩形，左→右 / 上→下）**：
1. **卡带插槽（cartridge slot）**：顶部中央偏左一道横向凹槽，宽度约为机身宽的 **30–38%**，深度约为机身高的 **10–14%**，内填深色 `#3A2E1C`（插卡口阴影）。这是"卡带选择"的**视觉锚点**——上传/拖拽交互的落点提示应环绕此槽。
2. **手柄接口（controller ports）**：机身正面右侧 2 个圆形/梯形插口（直径约为机身高的 **22–28%**），焦糖棕描边。
3. **电源/复位按钮**：正面左侧两个小圆/方按钮（直径约为机身高的 **14–18%**），一个暖橙红（电源）、一个米白（复位）。
4. **丝印文字**：机身正面可印极简字样（如 "FAMILY" / "TV-GAME" 风格），使用焦糖棕，字号约为机身高的 **10%**，圆体/像素体。

**绘制依据**：该机身**仅作装饰插画**，不承载真实交互逻辑；真实文件选择/拖拽由第 8 节的 UI 面板与卡带槽高亮共同完成。机身插画建议与电视外壳同属一个 SVG/CSS 变量体系，保证塑料质感一致。

## 5. CRT 着色器 / 扫描线叠加规格（高保真重点）

> 本节给出**工程可落地的参数区间**，而非仅描述。实现方式见 5.0 推荐栈。

### 5.0 推荐实现栈（给工程主程的决策建议）

| 档位 | 实现方式 | 适用 | 保真度 | 成本 |
|---|---|---|---|---|
| **基线档（必做）** | **CSS 合成叠层** | 所有设备、WebGL 不可用、reduced-motion 兜底 | 中 | 极低（GPU 合成，无逐帧 JS） |
| **高保真档（目标）** | **WebGL 片元着色器后处理** | 桌面/主流移动端，支持 WebGL | 高 | 中（需 WebGL 管线，仍是 Vanilla，无框架） |
| 备选 | SVG 滤镜（feDisplacementMap 做畸变 + feTurbulence 做噪点） | 轻量畸变/噪点 | 中低 | 低–中，但实时作用于 canvas 易掉帧 |

**结论**：
- **主推 WebGL 后处理**做高保真 CRT（桶形畸变、扫描线、辉光、色散、暗角、噪点一次片元着色完成，性能最优）。参考成熟方案：Lottes CRT / crt-royale 思路，自行精简为单 pass。
- **永远保留 CSS 叠层基线**：若 WebGL 初始化失败，自动降级为 CSS 叠层（扫描线用 `repeating-linear-gradient`、暗角用 `radial-gradient`、辉光用 `filter: blur()` + `screen` 混合、噪点用动画伪元素或 SVG turbulence 背景）。保证"无 WebGL 也有 CRT 味"。
- **reduced-motion**：两类档位均提供"静态精简版"（仅轻微暗角 + 低强度扫描线，关闭滚屏/噪点动画）。

### 5.1 各效果参数区间（跨实现方式通用）

| 效果 | 参数 | 推荐区间 | 说明 / CSS·WebGL 落地提示 |
|---|---|---|---|
| **桶形畸变（Barrel）** | 曲率 k | `0.06 – 0.16` | WebGL：纹理坐标按 `r²·k` 外推；CSS 近似：屏幕 `border-radius: 18–28px` + 内阴影 + 轻微 `scale(1.02)` 伪造鼓起。强畸变 >0.2 会过度变形，谨慎。 |
| | 边缘收缩 | 屏角内缩 `2% – 5%` | 畸变后四角留黑，用 vignette 掩盖。 |
| **扫描线（Scanline）** | 线频率 | 每 **2–4 物理 px** 一条暗线 | WebGL：依输出分辨率动态；CSS：`repeating-linear-gradient(0deg, transparent 0 2px, rgba(0,0,0,a) 2px 4px)`。 |
| | 暗线不透明度 a | `0.15 – 0.35` | 暗背景/亮屏取低值，过强会糊画面。 |
| | 孔栅（Aperture grille） | RGB 竖条 `0.10 – 0.25` 不透明度 | 模拟荫罩，WebGL 用 RGB 掩码；CSS 用 `repeating-linear-gradient(90deg,...)` 叠加。可选项，弱屏显设备建议关闭。 |
| **辉光/泛光（Bloom）** | 模糊半径 | `2 – 6 px`（亮部） | CSS：`filter: blur()` 亮部拷贝 + `mix-blend-mode: screen`，强度 `0.25 – 0.55`。WebGL：阈值提取亮部 → 降采样模糊 → 叠加。 |
| | 泛光强度 | `0.30 – 0.60` | 与扫描线叠加时注意不要过曝。 |
| **暗角（Vignette）** | 内圈半径 | 屏宽 `55% – 75%` 起透明 | `radial-gradient(ellipse, transparent 60%, rgba(0,0,0,v) 100%)`。 |
| | 边缘暗度 v | `0.30 – 0.60` | 与桶形畸变四角黑边协同。 |
| **色散（Chromatic Aberration）** | RGB 通道偏移 | `1 – 3 px`（或屏宽 `0.2% – 0.6%`） | WebGL：R/B 通道按径向偏移采样；CSS：三层 `text-shadow`/`box-shadow` 近似或叠 `mix-blend` 偏移层。边缘强、中心弱（按距中心归一化）。 |
| **噪点（Noise / Grain）** | 颗粒不透明度 | `0.04 – 0.10` | CSS：SVG `feTurbulence` 背景或动画 `background-position` 翻页；WebGL：哈希噪声。更新频率 `8 – 16 fps`（无需 60fps，省电）。 |
| **滚动横条（Rolling bar）** | 亮带高度 | 屏高 `6% – 12%` | 一条半透明亮带（暖白低 alpha）自上而下扫过，周期 `6 – 10 s`，模拟电源滚屏。可被 reduced-motion 关闭。 |
| **轻微闪烁（Flicker）** | 全局亮度抖动 | `±0.5% – 2%` | 50/60Hz 微弱闪烁，频率 `≥ 50 Hz`（不引起光敏）。reduced-motion 关闭。 |

### 5.2 强度档（供设置项 / 设备分级）

- **低（省电/移动端/弱 GPU）**：畸变 k=0.06、扫描线 a=0.18、无孔栅、bloom=0.30、vignette=0.35、色散=1px、噪点关、滚屏关。
- **中（默认）**：畸变 k=0.10、扫描线 a=0.25、孔栅 0.15、bloom=0.45、vignette=0.45、色散=2px、噪点 0.06、滚屏开(8s)。
- **高（桌面旗舰）**：畸变 k=0.15、扫描线 a=0.32、孔栅 0.22、bloom=0.55、vignette=0.55、色散=3px、噪点 0.08、滚屏开(7s)。

> 所有数值均可由用户"CRT 强度"滑块映射；工程需保证滑块能实时切换上述区间，且 reduced-motion 强制锁定为"低档静态版"。

## 6. 字体排印（Typography）

**字体策略**：拉丁/数字用像素体（bitmap）彰显复古；中文用系统圆体保证可读。全部通过 CSS `@font-face` + `font-family` 回退链，避免硬依赖外部网络（可内置子集或仅用系统字体）。

**字体回退链（建议）**：
- 显示/标题（拉丁数字）：`'Press Start 2P', 'Courier New', monospace`（像素体；中文回退见下）。
- 中文圆体：`'PingFang SC', 'Microsoft YaHei', 'Hiragino Sans GB', 'Heiti SC', sans-serif`。
- UI 正文：系统圆体/无衬线同上，`-apple-system, 'Segoe UI', system-ui` 兜底。
- 中文像素体（可选增强）：若引入中文像素字体（如 `Zpix`/`捆兔`），限定仅用于标题与 HUD，正文仍用圆体保可读。

**字号层级（以桌面基准，移动端按 0.8× 缩放）**：
| 层级 | 用途 | 字号 | 字重/字距 |
|---|---|---|---|
| Display | 主标题/Logo | `40 – 56 px` | 像素体，字距 `+2px` |
| Title | 面板标题 | `24 – 32 px` | 圆体 Bold |
| Section | 区块标题 | `18 – 22 px` | 圆体 SemiBold |
| Body | 说明/提示正文 | `14 – 16 px` | 圆体 Regular，`line-height 1.6` |
| Caption | 卡带名/状态 | `12 – 13 px` | 圆体/等宽 |
| HUD | 屏幕内小字（如"PRESS START"） | `10 – 12 px` | 像素体 |

**排印禁忌**：游戏画面内文字走 NES 原生位图字（由 ROM 决定），本系统字体只用于**外壳 UI 与网页 chrome**，两者风格需协调（均偏圆/像素，避免引入现代无衬线细体破坏氛围）。

## 7. 开机动画分镜（Boot Animation Storyboard）

旧电视开机：黑屏 → 中心白点 → 横向亮线 → 扫描线滚入 → 画面稳定。总时长建议 **1200 – 1500 ms**，缓动用 `ease-out-cubic` 为主。

| 帧 | 时间窗 | 画面 | 关键参数 / 缓动 |
|---|---|---|---|
| **F0 断电待机** | `0 – 150 ms` | 纯黑屏，极淡 CRT 噪点（噪点 a≈0.05） | 无 |
| **F1 中心白点** | `150 – 350 ms` | 屏幕正中一个白色圆点由 `r≈6px` 渐显并扩至 `r≈14px`（显像管电子束点） | 透明度 `0→1` 缓入；圆点带微 glow |
| **F2 横向亮线** | `350 – 650 ms` | 白点横向拉伸成贯穿全宽的细亮线（高 `2–4px`），略带 overshoot 再回弹 | 横向 `scaleX 0→1.08→1`，`ease-out-back` |
| **F3 纵向展开 + 滚屏** | `650 – 1100 ms` | 亮线纵向展开铺满屏（`scaleY 0→1`），同时一条亮带自上而下扫过（滚屏登场） | 纵向 `ease-out-cubic`；滚屏带高 `8%` 屏高 |
| **F4 稳定** | `1100 – 1500 ms` | 画面淡入（待机雪花/磷光绿或已选卡带画面），扫描线、暗角、辉光叠加逐次"落定"，闪烁收敛 | 各叠加 opacity `0→目标值` 线性；末段亮度微抖 `±1%` 后归稳 |

**交互衔接**：F4 结束即进入"可操作态"——若已选卡带则显示游戏画面；若未选则显示待机雪花 + "插入卡带 / 选择文件"提示。

**减弱动效（reduced-motion）**：用户开启 `prefers-reduced-motion: reduce` 时，**跳过 F0–F3，直接呈现 F4 稳定态**（可保留一次 <200ms 的淡入）。见第 9 节 Standard 级。

## 8. 版面构图（Layout Composition）

**主结构（自上而下、水平居中）**：
1. **顶部留白 / 标题区**：页面顶部约 `8 – 12%` 视高放标题（Display 级）与一句氛围副标题；暗暖背景。
2. **电视机（视觉焦点）**：屏幕区最大宽度建议 `min(60vw, 720px)`，保持 4:3；居中。电视外壳用第 3 节规格。
3. **小霸王机身（装饰 + 卡带锚点）**：紧贴电视下方（或电视支脚搭其上），宽≈电视宽，按第 4 节绘制；**卡带插槽**作为拖拽/上传落点的视觉锚。
4. **卡带选择区 / 提示文案**：
   - 默认态：在机身插槽上方或下方浮出 UI 提示面板（半透明暖色卡片，圆角，焦糖棕描边），文案如"拖入 .nes 卡带 / 点击选择 / 使用内置游戏"。
   - 选中态：面板收缩为该卡带名（Caption 级）+ "点击电视开始" 提示；插槽高亮（暖橙红描边 + 微 glow）。
5. **底部留白 / 页脚**：版权/操作提示（移动端虚拟按键说明），低对比次要文本。

**留白与响应式**：
- 桌面（≥1024px）：电视居中，两侧留白 ≥ 20vw，机身与电视间距 ≤ 16px（视觉接驳）。
- 平板（640–1023px）：电视宽 `min(80vw, 560px)`。
- 移动端（<640px）：电视宽 `92vw`；虚拟按键区移至机身下方独立区块；卡带面板改为全宽底部抽屉式，避免遮挡屏幕。
- 安全区：所有 UI 文本距视口边缘 ≥ 16px；交互元素最小点击区 ≥ 44×44px（移动端可访问性）。

**视觉层次**：屏幕（亮、动）> 电视外壳（中明度塑料）> 机身插画（同系塑料）> 背景（暗暖）。强调色仅用于可交互元素，避免满屏橙红。

## 9. 可访问性分级（Accessibility Tiers）

本项目可访问性为**基础要求**。三级目标，至少落地 **Standard**。

### Basic（基础可达）
- [ ] 所有正文/UI 文本与背景对比度 ≥ 4.5:1（AA）。
- [ ] 所有交互元素可通过指针点击，**且可获得可见焦点**（`:focus` 轮廓，至少 2px）。
- [ ] 语义化结构（`<button>`/`<input>`/`<main>` 等），不使用纯 `<div>` 伪造按钮。
- [ ] 卡带选择提供**真实 `<input type="file" accept=".nes">`**（不只有拖拽，拖拽是增强不是唯一路径）。
- [ ] 图像化元素（电视/机身）纯装饰，`aria-hidden="true"`，不干扰读屏。

### Standard（标准，默认目标）
在 Basic 基础上：
- [ ] **键盘完全可达**：Tab 顺序合理，卡带选择、开始、CRT 强度调节均可纯键盘操作；焦点环用高对比亮黄 `#FFD23F`（见 2.4）。
- [ ] **`prefers-reduced-motion: reduce` 支持**：跳过第 7 节开机动画（直达稳定态）；关闭滚屏/噪点/闪烁动画；CRT 叠加降级为静态低档。
- [ ] 上传/拖拽失败有明确**文本错误提示**（非仅靠颜色），如"文件类型不支持，请选择 .nes"。
- [ ] 状态变化（加载中/就绪/错误）有文本或 `aria-live` 播报，不只靠颜色/图标。

### Comprehensive（全面友好）
在 Standard 基础上：
- [ ] **完整色盲友好**：强调色不单独承载信息；错误/成功除颜色外有图标或文字；提供"高对比/色盲安全"配色切换（用 2.4 中已定义的冷暖对比 + 图标双重编码）。
- [ ] **屏幕阅读器完整标签**：卡带文件名、CRT 强度档位、开始按钮均有 `aria-label`/`aria-describedby`；动态区用 `role="status"` + `aria-live="polite"`。
- [ ] **所有交互可键盘操作且无陷阱**：模态/抽屉可 Esc 关闭、焦点可循环且不丢失；虚拟按键在移动端亦可通过外接键盘映射。
- [ ] **文本可缩放**：支持浏览器 200% 缩放不破版；字号用 `rem`/相对单位。
- [ ] **光敏安全**：闪烁频率 ≥ 50Hz、单次闪烁面积 < 25% 屏、提供"关闭闪烁"开关（呼应 5.1 闪烁项）。
