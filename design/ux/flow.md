## 1. 卡带选择状态机（Cartridge State Machine）

> 状态集合：`Idle → Browsing → Loading → Playing`，可经"返回"回到 `Idle` / `Browsing`。
> 核心规则：**三种来源（内置 / 上传 / 拖拽）全部汇入 `Loading` 状态**，保证校验与进入逻辑单一、一致。

### 1.1 Idle（待机）
- **进入条件**：首屏渲染完成，CRT 电视显示"待机"（静态雪花 / 无信号噪点）+ 机身图案。
- **界面元素**：CRT 电视（待机画面）、小霸王机身、底部"插入卡带"提示、三个来源入口（内置卡带 / 上传文件 / 拖拽到此）。
- **可操作项**：
  - 点击「内置卡带」 → 进入 `Browsing`
  - 点击「上传文件」 → 触发系统文件选择器，选定后 → 进入 `Loading`
  - 拖拽 `.nes` 文件到电视区域（见 §5） → 进入 `Loading`
  - 点击电视屏幕本身 → 若已"预选"卡带则直接开机；否则提示先选卡带
- **异常**：无（首屏不接受文件，仅展示入口）。

### 1.2 Browsing（浏览内置）
- **进入条件**：用户点击「内置卡带」入口。
- **界面元素**：卡带网格（封面缩略图 + 名称）、分类/搜索（Could）、返回按钮。
- **可操作项**：
  - 选择某卡带 → 进入 `Loading`
  - 返回 → 回到 `Idle`
- **异常**：manifest 为空 / 加载失败 → 显示占位卡（"暂无内置卡带"），仍可走上传/拖拽。

### 1.3 Loading（加载中，含进度 / 校验）
- **进入条件**：选定内置卡带 / 上传文件 / 拖拽 drop 文件后。
- **界面元素**：进度指示（解析百分比 或 不确定动画）、校验状态文案（"正在读取卡带…"）、可取消按钮。
- **可操作项**：取消 → 回 `Idle`（来自上传/拖拽）或 `Browsing`（来自内置）。
- **异常（必须处理，统一回 Idle 并一句人话提示）**：
  - **(a) 非 `.nes` 扩展名** → "这不是 .nes 卡带文件" → 回 `Idle`。
  - **(b) 魔数校验失败（非 NES 头部 `$4E $45 $53` / iNES 头异常）** → "卡带数据损坏或格式不支持" → 回 `Idle`。
  - **(c) 文件过大（> 上限，建议 8MB）** → "卡带文件过大（上限 8MB）" → 回 `Idle`。
  - **(d) 解析 / 注入 jsnes 失败（超时或异常）** → "卡带读取失败，请重试" → 回 `Idle`。
- **成功**：jsnes 成功 `loadROM` 且首帧就绪 → 触发开机动画 → 进入 `Playing`。

### 1.4 Playing（游玩）
- **进入条件**：jsnes 载入成功 + 开机动画（§2）结束。
- **界面元素**：放大占满视口的 CRT 游戏画面、可选 HUD（帧率 / 存档按钮，Should/Could）、移动端虚拟按键（§4）、退出 / 全屏按钮。
- **可操作项**：
  - 键盘 / 虚拟按键操作游戏（§3 / §4）
  - 退出（Esc / 退出按钮） → 回 `Idle`
  - 全屏（Should）、存档（Could）
- **异常**：ROM 运行期崩溃（jsnes 抛错 / 黑屏） → 捕获错误 → 提示"游戏运行出错" → 回 `Idle`。

### 1.5 返回（Return）
- **进入条件**：用户退出 `Playing`。
- **界面元素**：回到 `Idle`（电视待机）或 `Browsing`（若来自内置）。
- **可操作项**：重新选择卡带 / 上传 / 拖拽，循环主流程。

```
        ┌─────────┐   选内置    ┌──────────┐
        │  Idle   │──────────▶│ Browsing │
        │ (待机)  │            │ (浏览)  │
        └────┬────┘◀──────────└────┬─────┘
             │ 选内置/上传/拖拽          │ 选卡带
             │ (统一汇入)               │
             ▼                         │
        ┌─────────┐   成功+动画     │
        │ Loading │──────────┐      │
        │ (加载)  │          ▼      │
        └────┬────┘      ┌────────┐ │
             │ 取消      │Playing │◀┘
             │           │ (游玩) │
             ▼           └───┬────┘
        Idle/Browsing        │ 退出/Esc
             ▲               ▼
             └──────────── Idle
```

## 2. 开机动画剧本（Boot Animation Script）

> 供美术与工程对齐的"镜头/阶段"描述。总时长约 **3.5–4.0s**，支持**点击 / 任意键快进**。
> 各阶段时长、缓动（easing）、是否配音频均为**可配置参数**（放美术/工程常量表）。

| 阶段 | 时间线 | 画面描述 | 缓动 / 技术点 |
|---|---|---|---|
| **S1 黑屏通电** | 0.0–0.4s | 纯黑，屏幕中心轻微"通电嗡"预备（音频待 §6 确认） | 无 |
| **S2 白点汇聚** | 0.4–1.2s | 中心白点由一点扩散成明亮圆斑（电子束点亮），外圈辉光 | ease-out，辉光半径渐增 |
| **S3 横向亮线** | 1.2–1.8s | 白点纵向拉伸成一条水平亮线（垂直回扫），屏幕上下抖动 | 弹性抖动，线宽渐稳 |
| **S4 滚屏展开** | 1.8–2.6s | 画面纵向滚动展开，浮现彩色噪点 / 雪花（无信号态），逐步收束 | ease-in-out，噪点密度递减 |
| **S5 信号锁定** | 2.6–3.2s | 噪点收束，显示卡带标题 / 品牌字或游戏首帧；CRT 曲面 + 扫描线就位 | 信号"啪"地锁定 |
| **S6 放大进入** | 3.2–4.0s | 电视画面放大占满视口，进入 `Playing` | ease-out，画面缩放 1→满屏 |

**对齐要点**：
- S2–S5 复用 CRT 后处理管线（见 concept §2.1），仅叠加"通电瞬态"参数；不可另写一套渲染。
- 快进：点击屏幕或按任意键跳过 S1–S5，直接 S6 进入。
- 弱设备（移动端）可在 `Loading` 阶段预渲染首帧，缩短 S4–S5 实际耗时。

## 3. 键盘映射表（Keyboard Mapping）

> 抽象为 NES 八路意图（D-Pad×4 / A / B / Start / Select）。以下为**默认**，全部可改键（设置面板，Should）。
> 注意：WASD 中的 "A" 键 = D-Pad 左（移动），与 NES "A 按钮" = J 不冲突，文档中已分开标注。

| NES 按钮 | 默认主键 | 备选键 | 说明 |
|---|---|---|---|
| D-Pad ↑ | `↑` Arrow | `W` | 上移 |
| D-Pad ↓ | `↓` Arrow | `S` | 下移 |
| D-Pad ← | `←` Arrow | `A` | 左移（WASD 的 A） |
| D-Pad → | `→` Arrow | `D` | 右移 |
| **A 按钮** | `J` | `Z` | 主攻击 / 确认（经典 Z 备选） |
| **B 按钮** | `K` | `X` | 副攻击 / 取消（经典 X 备选） |
| **Start** | `Enter` | — | 开始 / 暂停 |
| **Select** | `Shift`(右) | `` ` `` 或 `Backspace` | 选择菜单 |

- **改键机制**：设置面板列出八路意图，点击后捕获下一次按键写入；冲突检测（同键不可绑两路）。
- **防冲突**：`Tab` 默认不占用（浏览器焦点切换），若需可放 Could。

## 4. 移动端虚拟按键映射（Mobile Virtual Pad）

> 输入逻辑与键盘**共用同一意图层**（D-Pad/A/B/Start/Select）；仅渲染与事件源不同。

### 4.1 屏幕布局
- **左侧**：十字方向键（D-Pad）。方案二选一（见 §4.3）：`nipplejs` 摇杆取 4 向离散输出，或自绘十字按钮。
- **右侧**：A / B 两个大圆按钮（A 在右、B 在左，符合右手拇指习惯；B 略小/略左）。
- **上方（右区之上）**：Select / Start 两个小长条按钮，并排。
- 布局随屏幕安全区（safe-area-inset）自适应，横屏优先，竖屏居中堆叠。

### 4.2 交互要求
- **多点触控**：方向 + A/B 需同时按下（如"右 + B 跳"），必须支持并发触控，禁止单点独占。
- **防误触**：`viewport` 设 `user-scalable=no`、按键区 `touch-action: none`，阻止页面滚动 / 双击缩放。
- **视觉反馈**：按下态高亮 + 轻微缩放，提升触感确认。

### 4.3 对接点（与 nipplejs / 自绘）
- **nipplejs 方案**：监听 `move` 事件的 `direction`（上/下/左/右）离散映射 D-Pad；`end` 事件清空中立。摇杆中心固定（不跟随手指），避免遮挡。
- **自绘方案**：`touchstart/touchmove` 计算触点相对中心的角度 → 4 向量化；`touchend` 复位。
- 两者最终都向**意图层**输出 `dpad:{up,down,left,right}` 布尔 + `button:{a,b,start,select}` 布尔，与键盘同源。

## 5. 拖拽上传交互规格（Drag & Drop）

> 桌面专属交互；移动端无拖拽，靠「上传文件」按钮补足（平台分治，见 concept 支柱 3）。

### 5.1 拖拽进入电视区域（dragover）
- 实时视觉反馈：电视机外框**高亮 / 发光**，屏幕中央显示"松开以插入卡带"，卡带缩略图标跟随光标或落在电视上。
- 拖拽离开（dragleave）→ 取消高亮，恢复待机。

### 5.2 drop 后校验流程
1. 取 `dataTransfer.files[0]`。
2. 检查扩展名 `.nes`（不区分大小写）→ 否则异常 (a)（§1.3）。
3. `file.arrayBuffer()` 读入 `ArrayBuffer`。
4. 校验前 3–4 字节 NES 魔数（`$4E $45 $53` / 字符串 "NES"）→ 不符异常 (b)。
5. 大小检查（> 8MB） → 异常 (c)。
6. 切片为 `Uint8Array` → `nes.loadROM(uint8)`；失败异常 (d)。
7. 成功 → 触发开机动画 → `Playing`。

### 5.3 校验失败
- 弹一句人话提示（对应 §1.3 文案），卡带图标"弹出"动画，回到 `Idle`。

## 6. 卡带清单数据结构（Manifest）建议

### 6.1 内置卡带（JSON manifest）
```json
{
  "version": 1,
  "cartridges": [
    {
      "id": "super-mario-bros",   // 唯一标识，用于分享/记录
      "name": "超级马里奥兄弟",     // 显示名
      "file": "assets/roms/smb.nes", // ROM 路径（构建期打包或 CDN）
      "cover": "assets/covers/smb.png" // 封面缩略图，可选
    }
  ]
}
```
- `id` 稳定、可读；`file` 相对站点根或 CDN；`cover` 缺省时网格用占位图。

### 6.2 上传 / 拖拽的 ROM 载入（→ jsnes）
- 来源：`File` 对象（上传选择器或 drop）。
- 载入：`const buf = await file.arrayBuffer();` → `const rom = new Uint8Array(buf);` → `nes.loadROM(rom);`
- jsnes `loadROM` 接受 `Uint8Array` / 二进制字符串；统一用 `Uint8Array` 避免编码问题。
- 解析前已完成的扩展名 + 魔数 + 大小校验（见 §5.2）是**前置门**，不依赖 jsnes 内部报错。

## 7. 工程对齐清单（给 engineering-lead 的待办提示）
- [ ] `nes.loadROM(Uint8Array)` 输入形态 + 头部魔数校验需在 `Loading` 实现并暴露错误码（对应 §1.3 a–d）。
- [ ] CRT 后处理管线需在"待机雪花"与"游玩画面"两种模式复用同一 shader/滤镜；开机动画 S1–S6 参数需可配置。
- [ ] 键盘 / 虚拟按键统一抽象成"意图层"八路输出，避免两套输入逻辑。
- [ ] 文件大小上限（建议 8MB）在 upload/drop 前置校验，避免大文件卡死解析。
- [ ] 移动端 `touch-action: none` + 多点触控并发；`viewport` 禁缩放。
